# 사이트 내용 관리

사이트에 보이는 글과 이미지는 전부 이 `content/` 폴더에 있습니다. 코드는 건드리지 않아도 됩니다.

```
content/
  profile/
    index.md        소개 페이지, 이름·이메일 같은 공통 정보
    photo.jpeg      프로필 사진
  projects/
    _template/      새 작업용 템플릿 (사이트에 안 보임)
    kinetic-void/
      index.md      작업 정보 + 본문
      cover.jpg     대표 이미지
      image-01.jpg  나머지 이미지 (파일 이름 순서대로 표시)
```

## 새 작업 추가하기

### 방법 1. GitHub 웹사이트에서 (PC 설정 없이, 휴대폰도 가능)

1. 저장소의 `content/projects` 폴더로 들어갑니다.
2. **Add file → Create new file**을 누르고, 이름 칸에 `새-폴더-이름/index.md`를 입력합니다. `/`를 치면 폴더가 만들어집니다.
3. `_template/index.md`의 내용을 복사해 붙여넣고 채운 뒤 **Commit changes**를 누릅니다.
4. 방금 만든 폴더로 들어가 **Add file → Upload files**로 이미지를 올립니다. 대표 이미지는 `cover.jpg`로 올립니다.
5. 1~2분 뒤 저장소의 **Actions** 탭에 초록 체크가 뜨면 사이트에 반영된 것입니다. 빨간 X가 뜨면 눌러서 오류 메시지를 확인하세요. 어느 파일의 무엇이 문제인지 한국어로 나옵니다.

### 방법 2. 내 PC에서

```bash
npm run new -- 새-폴더-이름
```

폴더와 `index.md`가 만들어집니다. 이미지를 넣고 `npm run dev`로 확인한 뒤 커밋하고 push하면 자동으로 배포됩니다.

## 규칙

- **폴더 이름**은 주소(URL)로 쓰입니다. 영어 소문자, 숫자, `-`만 씁니다. 예: `rebar-auto-placer`
- **필수 항목**은 `title`, `category`, `year` 세 개뿐입니다. 나머지는 없어도 됩니다.
- **category**: `development`(개발), `bim`, `architecture`(건축 설계)
- **순서**: 분류별로 최신 연도가 위에 옵니다. 같은 연도끼리는 `order`가 작은 것이 위입니다. 도면번호(D-01 등)는 이 순서대로 자동으로 매겨집니다.
- **이미지**는 jpg, png, webp를 쓸 수 있습니다. 휴대폰 사진처럼 큰 파일은 가로 1600~2000px 정도로 줄여서 올리면 사이트가 빨라집니다.
- **대표 이미지**: `cover.jpg` → 없으면 파일 이름순 첫 번째 이미지. `cover: 03.jpg`처럼 직접 고를 수도 있습니다.
- **수상한 작업**은 `award: 2019 BIM AWARDS 우수상`처럼 적으면 작업 페이지와 목록 미리보기에 표시됩니다.
- **작성 중인 작업**은 `draft: true`를 넣으면 배포된 사이트에서 숨겨지고, 내 PC(`npm run dev`)에서만 '초안' 표시와 함께 보입니다.
- 값 안에 `:`이나 `#`이 들어가면 `"따옴표"`로 감싸주세요. 예: `summary: "결과: 보고서 자동 생성"`
- 다른 작업으로 가는 링크: `[JHSLab Add-in](#/projects/jhslab-addin)`
